# Legacy backport architecture and feature audit

The original root `src/` and `modern-reference/` retain the Forge 1.20.1 source and build reference. Production legacy targets are independently owned by `versions/1.7.10` and `versions/1.12.2`; both must run on Java 8. The Gradle launcher uses JDK 25; compilation uses Java 8 on 1.7.10 and JDK 21 with `--release 8` on 1.12.2. Portable code belongs in `common/`; Minecraft and Forge types do not.

The root `version.properties` owns the shared mod release version. `gradlew release` orchestrates both production builds and collects only their final distribution JARs under `build/release/`; see [building and releases](building.md) for commands, toolchains and artifact naming.

## References examined

- [Forge 1.20.1](https://github.com/McJtyMods/LostCities/tree/f18a094d710a0957ead20dc24f0bf1365b885802), the repository's original snapshot.
- [Original Forge 1.12](https://github.com/McJtyMods/LostCities/tree/e89000238a8095cba8a739fc3b9e595d854a1346), the legacy behavior and API reference (2.0.22).
- [NeoForge 1.21.11](https://github.com/McJtyMods/LostCities/tree/2c3599a1350966d0236b8d6256eac84ca75d21dd), including recent generation, transit, asset, and lifecycle fixes.

Modern systems requiring migration include hierarchical streets, intercity highways, arbitrary multibuilding footprints, scattered structures, noise-based cities, configurable railway spacing and height, palette variants, style overrides, road/support parts, and modern block-state strings. Original 1.12 already implements overlapping radial cities, styles, buildings and 2x2 multibuildings, cellars and corridors, bridges, tunnels, highways, rail stations and dungeons, damage, ruins, vines, loot, spawners, predefined cities, and floating/cavern/space landscapes. Preserve those reference algorithms rather than substitute simple box buildings.

`HIGHWAY_MAJOR_CITY_PLAN.md` describes a proposal. The inspected production `IntercityHighwayPlanner` still selects point-potential hubs and requires reciprocal connections. Concentration scoring, mandatory first connections, duplicate suppression, and emergency searches must not be advertised as upstream functionality.

## Port boundaries

| System | Legacy implementation requirement |
| --- | --- |
| Profiles and saves | Preserve identifiers and old option meanings; persist generation modes per world |
| Assets | Load legacy libraries and modern JSON assets; validate references, dimensions, selectors, palettes |
| Materials | Semantic resolver; native first, optional UAB/configured providers, functional native substitutes |
| Placement | Native 1.7.10 blocks/metadata and native 1.12.2 states; clip to 0–255 |
| Terrain | Preserve Forge events, biome providers and configured adapters; no remote planning chunk loads |
| Execution | Server-owned synchronous placement; portable pure planning and asset processing |
| Loot/spawners | Native loot tables on 1.12.2; inventories, weighted loot and spawner NBT on 1.7.10 |
| Compatibility | Actual registry/state availability; no mandatory UAB, BOP, UBC or cave-mod dependency |

Modern city chunks save sparse native fallback snapshots for optional block families selected by Lost Cities. On provider removal, the native chunk-load stage restores missing cells and supported block-entity inventories from these snapshots before the chunk becomes active, without regenerating the chunk or changing surviving blocks. Orientation and representable slab/door states are translated while the provider still exists. Barrel substitutes alternate native normal and trapped chests by horizontal position, keeping adjacent barrel inventories separate; the trapped variant has vanilla redstone behavior. Palette aliases inherit functional metadata and respect the final local override layer. Every existing chunk to be protected must be loaded and saved with the provider and this backport installed to acquire a snapshot; an already-removed block without a snapshot cannot be recovered. Forge's normal missing-mod confirmation still applies. This is scoped to Lost Cities materials, not a general migration of a removed mod's unrelated blocks, items, entities or biomes.

## Native behavior

Modern mode uses the actual upstream reciprocal-selection highway planner, hierarchical street planner and final road filtering, area-based variable-footprint multibuilding placement, and railway grid with separate axis spacings and safe station descents. Scattered structures select and validate a complete footprint before any section is placed; roadside buildings align to a common non-tunnel highway elevation and open the adjoining iron-bar railing. Automatic roads require a connected raw city neighbor and yield to predefined content and multibuildings. Street parts use this final road class, and accepted straight slopes connect both their lower and upper road endpoints, opening the upper border from the slope part metadata. Inherited city-style park, foliage, fountain, front and corridor settings resolve once against the selected profile. Parks support custom palette grass, optional borders and elevation thresholds. Column decorations use bounded attempts against the local primer. These stages do not load remote world chunks for planning.

The startup asset compiler accepts flat overrides and namespaced data/<namespace>/lostcities layouts, checks cross-asset references and inherited city-style cycles against both catalogs, retains source slices, expands palette variants, validates part dimensions, and transposes modern column-major multibuildings to the native legacy loader's row layout. Materials are resolved before world creation, with all unresolved palette states reported together. Building and part palettes are layered in their original order. Aliases are resolved without recursion after material overrides; inherited self-aliases retain their material, and functional metadata follows the final alias graph. Legacy fallback assets have independent modern instances, so lazy inheritance cannot contaminate another world’s catalog. Explicit legacy @0 states retain metadata zero rather than selecting the block’s default orientation; absent metadata starts from the native default state. Templates preserve representable native orientation, hinges, slab halves, rails, block-entity data, inventories and spawners. Cellars and floors respect the native 0–255 height limit. Modern 1.12 terrain corrects the legacy density interpolation error; legacy-mode worlds retain the previous formula.

The native adapters preserve Forge terrain/noise/decorating events. Forge cave replacements retain their ownership. YUNG’s Legacy Better Caves uses an optional native adapter because its stock hooks deliberately reject custom chunk providers; its own carving engine, native terrain buffers, liquid resolution, flooded ravines and per-dimension configuration remain authoritative. Adapter discovery is cached at generator construction and carving stays on the server thread. This adapter targets the com.glowingfederal Better Caves implementation; it does not claim arbitrary forks with different APIs. Non-default landscapes retain their native carving. Vanilla fallback on both targets honors maxCaveHeight. Underground Biomes can participate through native terrain/population hooks. BOP delegation uses the biome manager belonging to the current world, including when profile biome restrictions are enabled. Both native targets support climate-weighted biome restrictions, manual mappings, and original/randomized/varied strategies. Restrictions translate the existing biome layers rather than creating a replacement biome distribution; coarse terrain samples and block-scale samples use the same world coordinates. Spawn and structure searches test translated biomes across the complete requested area. Configured `lc_<worldtype>` adapters require that generator's native `IChunkPrimerFactory` implementation and fail clearly when it is absent. A compatible interface is required; arbitrary dimension generators are not automatically interchangeable. General `overlayDimensions` entries can opt normal overworlds or compatible dimensions into city generation while retaining their saved world type and native biome layers. Installation uses Forge CreateSpawnPosition and World Load events before chunk generation. Exact native overworld implementations provide their own base terrain and non-city surface stage; custom generators implement `IChunkPrimerFactory`, whose optional `replaceSurface` default method preserves compatibility with older adapters. The selected city profile controls caves, structures and population. Unsupported generators and non-default landscapes fail explicitly. Completed chunks are loaded normally and never regenerated.

Vanilla 1.7.10 has no ocean-monument or woodland-mansion generator. Its inventories use Forge weighted loot hooks and the bundled Lost Cities loot definitions. Newer vanilla chest categories select corresponding legacy tables; 1.12.2 uses native loot tables and fills optional inventories that do not support vanilla deferred loot. Custom loot namespaces remain separate from the built-in alias rules. Modern loot resources can use `modern/data/<namespace>/loot_tables/<path>.json`, the newer `loot_table` spelling, or `modern/loot_tables/<namespace>/<path>.json`. Constant and uniform number providers and vanilla namespaced operation identifiers compile to native JSON; pool/table item functions are applied in their original order. Definitions are retained in the world’s standard data/loot_tables directory. Existing unowned or locally edited world tables keep precedence, and removing an asset pack does not delete retained tables. Native 1.12.2 uses the actual Forge loot manager, events, functions, conditions and deferred chest format. Native 1.7.10 supports weighted item/empty/table entries, references with cycle checks, random-chance/inverted/alternative conditions, counts, item data, durability, compound NBT and native enchanting. Chest contexts have no killing player or looting level. Item and enchantment identifiers must exist in the target registry; unsupported operations fail with the table name. Additive functions, nonuniform/nonconstant number providers and functions applied to referenced table entries require a newer engine and are rejected rather than silently discarded. Native 1.7.10 retains its Forge chest hooks for unmapped vanilla table categories.

Generation stays on the owning server thread. Nested generation scopes restore the legacy palette random state and the generator’s profile-specific base/liquid materials. Profile materials refresh when entering a scope rather than only at initial character setup. Hard-air markers remain unrotated and are consumed by the placement stage rather than appearing as command blocks. `fastTerrainPlanning` defaults to true. It samples the native density lattice at the same five positions as the full native height planner; it can be disabled for diagnosis. Custom terrain factories, floating worlds, spheres and caverns retain full native sampling. Saved material choices cover the whole modern asset pack, and both present and absent highway hubs persist per dimension. Deferred loot, spawner, tree, lighting and block-entity work also persists across restarts. Metadata caches belong to each native generator, so unloading and recreating a dimension cannot reuse another world’s building, biome, highway or sphere state. Completed metadata and raw terrain caches are bounded. Active generation and uncaptured population work stay pinned; saved deferred work can be evicted and is restored from world data when needed. Deferred conditions retain the actual placement’s building, floor, cellar, below-part and chunk inputs, including scattered structures and neighboring building fronts. Older pending records without these fields derive their context from the actual block’s chunk. Editing profiles, asset packs or provider mappings remains a deliberate world-generation change.

On 1.7.10, integrations can send an IMC string message with key `getLostCities` and the callback class name. The callback implements Java's or Guava's `Function<ILostCities, ?>`; the public API also remains available through `LostCities.lostCitiesImp`. The 1.12.2 function-message API is retained. Native 1.7.10 clients receive the server-selected fog, horizon and ground-level presentation values through bounded packet queues. Server profile reads run on the server tick, and client render values publish on the client tick; disconnects and server shutdown clear pending state. World styles resolve after saved generation mode becomes available, so modern-only namespaced styles work during native world construction. Native 1.12.2 retains its profile-name protocol while separating server profiles from client caches; connection epochs and native connection identities discard stale queued replies and force a fresh request after reconnecting. Normal-world overlays retry initial presentation discovery and cache explicit non-city responses, keeping ordinary worlds free of city fog. The existing dimension/string packet layout is retained; an empty profile marks a non-city dimension.

## Qualification

Compilation, production remapping, Java 8 startup, deterministic planning, chunk generation, persistence, optional-provider matrices and visual gameplay are separate checks. A build alone does not establish feature parity. Target-specific status and supported options are documented as implementation lands.

Native BOP 7 overworld overlays call the original base-terrain and surface methods and reuse its authoritative temple, mansion, monument, village, stronghold and mineshaft instances. Planning queries the same canonical structure generators without loading chunks. Standard city dimensions retain their LostMansion save identity; BOP overlays retain the native Mansion identity. The terrain adapter API can optionally supply canonical structures with getStructureGenerator; older implementations inherit a null default. Profile switches still own cave and population choices. No BOP source or binary is embedded.

On 1.12.2, BOP biome providers are constructed through BOP's native seed/world-type/settings constructor, using the registered BOP world type. This also supports extra dimensions backed by native derived world information when the overworld uses another world type. The saved overworld header is never temporarily changed to construct these layers. Both the extra-dimension and `lostcities_bop` paths use this optional boundary; BOP remains unnecessary when its biomes are not selected.

The additional spheres and cavernspheres landscape types use native overworld/cavern density terrain, the existing deterministic sphere layout and the modern two-block shell/clearing algorithm, clipped to Y 0–255. They do not require the modern Lost Worlds dimension generator. Native space retains its original floating bubble terrain and monorails. Sphere shell clearing options are bounded to the actual legacy build height. The new profiles remain available privately when an older public-profile list omits them. Fresh extra dimensions select modern mode from their own saved terrain presence, rather than the timing of overworld level.dat creation; existing saved mode markers take precedence.

Native operator editor commands use the sender world and its asset/material/generation scope. Part placement shares the production palette and functional-marker path; exports contain exact native block metadata, native block-entity SNBT and local palettes. Building exports include six-block floor parts and a selectable building definition. Exported block-entity data uses the reserved tag object field $snbt; placement reads it through the native NBT parser and retains destination identity and coordinates. Existing JSON tag objects remain supported. Editor export counts must fit the native height; these tools require permission level 2.

Special-bed travel on both targets searches at most 64 destination chunks. The native destination keeps priority for a matching special bed, then safe standing space, with a bounded floor/headroom fallback in void or liquid-only areas. Disabled spheres do not initialize a building palette, avoiding a recursive height-planning cycle. Explicit editor placement supplies its own structure context while retaining the profile controls for loot and spawners.

Editor deferred work follows native population ownership: a part contained in one chunk can enqueue work in that chunk and its west, north and northwest owners. Before placement, stale tags, loot, spawners, saplings and lighting jobs are removed only inside the part's bounds. Completion visits those same four owners, processes only positions inside the edit and saves the remaining queues. Torch orientation work is local to the part's chunk and uses the same bounds filtering. Ordinary population continues to process its complete owner queue. Profile loot/spawner switches and the configured empty-chest chance still apply to explicit placement.

New-world mode detection checks saved region terrain in the overworld as well as extra dimensions. The native singleplayer client may write `level.dat` before constructing the first generator, so a world header alone does not imply legacy terrain. A saved mode marker always wins; unmarked dimensions with existing region files retain legacy generation.

An explicit mob condition owns both the current spawner identity and its weighted spawn pool. Resolution retains the native delay, range and entity properties while replacing the pool with the selected entity, so a later native reset cannot restore an old Pig entry. Editor changes notify native clients. NBT-only imported spawners without a mob condition retain their complete exported pool.
